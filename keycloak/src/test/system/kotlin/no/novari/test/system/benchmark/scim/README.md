# SCIM Benchmarks

Requires Java 21 and Docker. JUnit starts the test environment, seeds users through
the Keycloak Admin API, runs k6 in a container, and cleans up afterward.
No local k6 installation is needed. Benchmarks are skipped unless explicitly enabled.

## Run

From `keycloak/`, run both benchmarks:

```sh
SCIM_SEARCH_BENCHMARK=true ./gradlew systemTest --tests '*ScimSearchBenchmarkTest' --rerun-tasks
```

To run just one, use either test selector:

- `*ScimSearchBenchmarkTest.benchmark SCIM searches`: different search filters and pages.
- `*ScimSearchBenchmarkTest.benchmark SCIM traversal`: all users via cursor pagination, checking for missing or duplicate users.

## Settings

| Environment variable | Default |
| --- | --- |
| `SCIM_BENCHMARK_USERS` | 10,000 (minimum 1,000) |
| `SCIM_BENCHMARK_WARMUPS` | 5 |
| `SCIM_BENCHMARK_ITERATIONS` | 30 |
| `SCIM_BENCHMARK_PAGE_SIZE` | 100 (traversal only) |

For a quick verification run:

```sh
SCIM_SEARCH_BENCHMARK=true SCIM_BENCHMARK_USERS=1001 \
SCIM_BENCHMARK_WARMUPS=1 SCIM_BENCHMARK_ITERATIONS=2 \
./gradlew systemTest --tests '*ScimSearchBenchmarkTest' --rerun-tasks
```

## Results

Reports are written to `build/reports/scim-search-benchmark/{searches,traversal}/`:

- `results.csv`: min, median, p95, and max timings in milliseconds, excluding warm-ups.
- `summary.json`: k6 metrics and checks.
- `report.html`: visual summary generated by k6-reporter (downloaded from GitHub during startup).
- `k6.log`: runner output.

Traversal reports individual page latency, summed request time per traversal, and
total elapsed traversal time. Each iteration reads the entire dataset.

Requests are sequential, not a concurrent load test. The test environment enables
Kover coverage, so compare runs on the same setup rather than treating results as
production latency. Failed checks fail the test; there are no latency thresholds.
